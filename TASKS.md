# DANK Capital: мобильное приложение для инвесторов. План задач

**Цель:** инвестор входит в приложение через Supabase и видит в телефоне всё то же, что в личном кабинете на dank.capital. Админская часть остаётся в WordPress.

**Принятые решения (3 ноября 2026):**
- **Стиль:** цвета, шрифты и изображения маркетингового сайта (тёмно-синий, бирюза, золото, Sora и Poppins), оформленные как мобильное приложение по лучшим практикам UI/UX. Структура и данные берутся из кабинета.
- **Данные:** WordPress отправляет custom fields пользователя в Supabase, синхронизация односторонняя.
- **Вход:** Supabase Auth, одноразовый код на email. Пароли WP не используются.
- **Заявки** (вывод средств, изменение профиля): приложение отправляет их на сайт в Gravity Forms, админ работает как раньше. В будущем возможны уведомления в Telegram.
- **Хостинг:** Vercel (https://dank-nine.vercel.app), потом свой домен.

**Как работаем:** задачи выполняются строго по порядку. После каждого шага останавливаемся, проверяем результат и получаем подтверждение, только потом переходим к следующему. Отметка `[x]` ставится, когда выполнен пункт «Готово, когда».

Документация для клиента: [docs/client/index.html](docs/client/index.html).

- [x] **3.3 Вход через Supabase:** `signInWithOtp` → код из письма → `verifyOtp`. Вывод средств тоже подтверждается кодом из email. Новые пользователи создаются только синхронизацией с WordPress.
- [ ] **3.4 Письма Supabase Auth (сейчас блокирует вход клиентов):** в шаблонах Magic Link и Confirm signup нужен `{{ .Token }}`. Встроенная почта Supabase отправляет письма только участникам команды проекта, поэтому для инвесторов нужен свой SMTP. шаблон письма с кодом в фирменном стиле, свой SMTP (Resend / Postmark) с адреса домена dank.capital.

> Решение: пароли WordPress не переносим (хеши phpass и `$wp$2y$` несовместимы с Supabase). Вход по коду из email работает для всех перенесённых инвесторов сразу. Позже можно добавить пароль или вход по биометрии.

### Шаг 4. Синхронизация WordPress → Supabase

- [ ] **4.1 Edge Function `wp-sync`:** проверка HMAC-SHA256 и метки времени (окно 5 минут), Zod-схема снимка, upsert по `wp_user_id`; если auth-пользователя нет, он создаётся через `auth.admin.createUser` с `email_confirm: true`. Обрабатывает и удаление.
- [ ] **4.2 WP-плагин `wordpress/dank-sync/`:** хуки `added/updated/deleted_user_meta`, `profile_update`, `user_register`, `delete_user`, `acf/save_post` (`user_*`) и хуки сохранения инвестиций и выводов (по карте из 1.5). Плагин собирает ID пользователей за запрос и на `shutdown` ставит одну задачу на пользователя в очередь Action Scheduler с повторами. Отправляется полный снимок, секрет хранится в `wp-config.php`.
- [ ] **4.3 WP-CLI:** `wp dank-sync push --all` (первичный перенос пачками) и `wp dank-sync push --user=<id>`.
- [ ] **4.4 Ежесуточная сверка:** `pg_cron` в Supabase помечает записи, которые давно не обновлялись; WP-cron досылает снимки.
- [ ] **4.5 Журнал синхронизации:** таблица `sync_log` (статус, ошибка, время) для диагностики.
  *Готово, когда:* правка поля в админке WP (сначала на staging) отражается в `profiles` меньше чем за 10 секунд; повторная отправка того же снимка ничего не ломает.
